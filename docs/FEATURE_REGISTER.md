## How to use and edit

1. In GitHub, open this file and click the pencil icon. Edit **Priority (0–5)**, **Attention**, **Your notes**, or **Next action**; commit your edits. In future chats, ask: **"Read the latest `docs/FEATURE_REGISTER.md` from melissamerica and use my current weights."**
2. Priority scale: **0 = drop/not wanted; 1 = someday; 2 = low; 3 = medium; 4 = high; 5 = critical.** Blank `—` means **not assigned by the owner**; do not guess it. **Attention**: `Yes`, `No`, or `—` (not assessed).
3. **Status** measures existing source and readiness, **not priority**: `Implemented in source` does not prove the live workflow works; `Partially implemented` means known limitations; `Staged, not deployed` is separate code; `Preview only` is a visual demo; `Proposed / gap` is an agreed desired correction, not delivered; `Concept` is exploratory.
4. Use stable IDs when discussing or changing features. Never overwrite someone's **Your notes** or weights when refreshing implementation status. Add new rows instead of silently dropping proposals. Review existing code and decisions before changing statuses.
5. Product-first principles: design for the worker doing the work; preserve approved functionality and brand. Keep live email/calendar delivery off until explicitly authorized. No general inbox triage, autonomous calendar reshuffling, focus defense, algorithmic scheduling, or utilization dashboards. Executive Time Tracker remains deferred.

**Current review boundary:** Based on repository records and selective source inspection, not a fresh end-to-end test. Existing notes report four routing/role tests passing and an empty signed-in workspace rendering; populated upload → itinerary → expense → approval was not verified here. Sources are navigation/evidence, not proof of current live delivery.

## Important distinctions and follow-up policy

- **Anya** is the EA-operated work surface; executive decisions, voice/video, texting and flight tracking involve explicitly authorized executive interactions. The original one-EA workspace is not a generic multi-editor collaboration app.
- **Alec** is a self-managed corporate professional's experience, not Anya renamed. Employer provisioning does not change the worker-first design philosophy.
- **Winnie** remains exploratory and **must not** be represented as shipped.
- The Decision Queue source lives in `docs/source-handoff/execos-staging-not-deployed/`; standalone previews and mock data are not live workflows.
- **Text as the Boss** constraints from November 1: exact existing executive personal number is mandatory; launch on easier platform then expand; support ongoing contact permissions and one-off conversation delegation; per-contact/executive configurable EA authority. Technical feasibility is unresolved.
- Existing requirements survey is **STOPPED**; do not restart or re-ask answered decisions. Feature-specific clarifications are appropriate only when a material unsolved choice blocks implementation.
- Owner's feature weights and notes are **intentionally unfilled**. Current ordering is grouping for navigation, not a proposed delivery sequence.
- When a feature is actually tested, add a dated verified result and any constraints to **Your notes** (or a linked test report). Do not change status to “verified” merely because code exists.
